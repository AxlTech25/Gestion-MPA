1. Introducción

Sigemad MPA V2 es una aplicación web para gestionar el inventario patrimonial de equipos de cómputo, sus fichas técnicas y el historial de intervenciones de mantenimiento. La plataforma incorpora un componente opcional de aprendizaje automático que estima el riesgo operativo y apoya la priorización del mantenimiento.

1.1 Objetivo general

Centralizar y mantener trazable la información del parque tecnológico, facilitando el registro, consulta, evaluación, mantenimiento y generación de reportes de los equipos.

1.2 Objetivos específicos

  • Controlar el inventario por código patrimonial, tipo, área, condición y estado operativo.
  • Conservar fichas técnicas y evaluaciones actualizadas por equipo.
  • Registrar intervenciones preventivas, predictivas, correctivas y de evaluación.
  • Proporcionar indicadores y gráficos para apoyar la supervisión del parque tecnológico.
  • Generar fichas e historiales en PDF.
  • Estimar el nivel de riesgo de los equipos mediante un microservicio ML opcional.

1.3 Público objetivo

PerfilUso principal del documento
AdministradorConfiguración organizacional, usuarios, seguridad y supervisión.
TécnicoInventario, fichas técnicas y registro de mantenimientos.
PracticanteConsulta y registro básico del inventario, según permisos.
Desarrollador / soporteInstalación, API, base de datos, pruebas y mantenimiento.

1.4 Metodología de desarrollo

El proyecto aplica la propuesta Prompt-Centered SDLC v1.2, en validación: se usa este software para comprobar si un ciclo de vida centrado en prompts puede sustituir a Scrum cuando la IA comprime los tiempos de implementación. No se aplican ceremonias ni sprints; las entregas se documentan como incrementos. La metodología puede tener lagunas; el detalle, las fuentes y las limitaciones están en documents/metodologia.md y en documents/desarrollo_softwareIA/.

3. Arquitectura de la solución

3.1 Vista general

│ HTTPS / JSON
▼

│ Proxy autenticado

La interfaz React consume una API REST desarrollada en PHP. El backend centraliza autenticación, reglas de negocio, acceso a MySQL y generación de documentos. Para las funciones predictivas, PHP actúa como proxy autenticado hacia FastAPI, evitando exponer directamente el servicio Python al navegador.

3.4 Flujo de una solicitud protegida

  1. El usuario inicia sesión con su usuario y contraseña.
  2. La API valida el hash de contraseña y emite un token JWT.
  3. El frontend incluye el token como Bearer en las solicitudes posteriores.
  4. El middleware valida vigencia, firma e identidad antes de ejecutar la ruta.
  5. La API responde en JSON; para reportes responde con el archivo correspondiente.

7. Manual de usuario

7.1 Inicio y cierre de sesión

  1. Abra la dirección de la aplicación.
  2. Ingrese usuario y contraseña.
  3. Seleccione la opción de acceso. Tras una validación correcta se mostrará el dashboard.
  4. Para finalizar, use Salir en la barra superior.

7.2 Dashboard

Presenta el total de equipos, mantenimientos, áreas y equipos dañados; gráficos por estado, tipo y área; categorías de falla; alertas predictivas y mantenimientos recientes.

Consulta por etiquetas

  1. Seleccione Consultar equipos.
  2. Aplique una o más etiquetas de tipo, estado operativo o conservación.
  3. Revise la tabla de coincidencias. Para tipos no estándar, seleccione Otro y escriba el tipo específico.

7.3 Inventario

Registrar un equipo

  1. Seleccione Nuevo Equipo.
  2. Ingrese un código patrimonial de exactamente 12 dígitos.
  3. Seleccione área y tipo. Si el tipo es Otro, especifíquelo.
  4. Para CPU o laptop, complete RAM, almacenamiento, procesador y sistema operativo.
  5. Verifique la información y seleccione Registrar Equipo.

Buscar, editar y exportar

  • Busque por código patrimonial, identificativo, marca o modelo.
  • Combine filtros de tipo y conservación.
  • Use el lápiz para editar, el documento para obtener la ficha PDF y el engranaje para abrir la evaluación técnica.

Carga masiva

  1. Seleccione Carga Excel y descargue la plantilla.
  2. Complete la plantilla sin alterar sus encabezados.
  3. Suba el archivo y revise el resumen de registros aceptados y errores.
  4. Corrija las filas observadas antes de repetir la importación.

7.4 Ficha técnica

  1. Abra Ficha Técnica.
  2. Ingrese el código patrimonial y seleccione Buscar Equipo.
  3. Revise datos generales, hardware, software, ubicación y condición.
  4. Actualice conservación, estado operativo y observaciones.
  5. Seleccione Guardar Evaluación. Use PDF para exportar.

7.5 Mantenimiento

El módulo muestra una línea de tiempo con intervenciones recientes y permite consultar un equipo mediante su código patrimonial.

Registrar una intervención

  1. Seleccione Registrar Intervención.
  2. Ingrese el código patrimonial y confirme el equipo identificado.
  3. Seleccione el tipo: preventivo, predictivo, correctivo o evaluación.
  4. Complete actividades, estado posterior y, según el equipo, telemetría.
  5. En un correctivo, documente síntoma, componente, causa raíz, diagnóstico, piezas y costo cuando corresponda.
  6. Guarde la ficha y verifique su aparición en el historial.
Tipo de equipoDatos específicos de mantenimiento
Laptop / CPUPolvo, temperaturas, horas de uso, batería e inactividad.
ImpresoraContador de páginas.
Monitor / OtroDatos generales, diagnóstico y actividades.

7.6 Configuración organizacional

Disponible para el administrador. La pestaña Áreas permite registrar unidades, jefes y descripciones. La pestaña Personal permite crear usuarios, asignar rol y relacionarlos con un área.

11. Base de datos y gestión de información

La base usa tablas con prefijo v2_ y columnas en snake_case. Los principales dominios son usuarios, áreas, equipos, fichas de mantenimiento, métricas por equipo y predicciones ML.

11.1 Reglas relevantes

  • El código patrimonial contiene exactamente 12 dígitos y actúa como identificador operativo.
  • Los usuarios se autentican con contraseñas almacenadas mediante hash.
  • Las fechas siguen formato SQL o ISO 8601.
  • La telemetría del equipo se sincroniza al registrar determinadas intervenciones.
  • Las migraciones deben aplicarse en orden y respaldarse antes de ejecutarlas.

11.2 Respaldo recomendado

  1. Genere un volcado completo de MySQL antes de cada despliegue o migración.
  2. Respalde las evidencias cargadas en backend/uploads.
  3. Proteja las copias con cifrado y acceso restringido.
  4. Pruebe periódicamente la restauración en un entorno aislado.

14. Seguridad y operación

  • Publicar únicamente mediante HTTPS.
  • Usar contraseñas únicas, robustas y rotarlas cuando exista una exposición.
  • Mantener el secreto JWT fuera del código y limitar su vigencia.
  • Aplicar el principio de menor privilegio a usuarios, base de datos y archivos.
  • Restringir CORS a los dominios autorizados.
  • No mostrar excepciones de base de datos al cliente en producción.
  • Actualizar dependencias de npm, Composer y Python después de validar compatibilidad.
  • Supervisar errores, accesos fallidos, espacio de almacenamiento y copias de seguridad.
  • Validar tipo, tamaño y nombre de archivos cargados.
